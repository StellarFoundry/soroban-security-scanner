# SS-034 — Unvalidated deployer usage

- **Severity:** high
- **Confidence:** low
- **Category:** access-control

## Problem

`env.deployer()` deploys or registers contracts and can upload or replace
contract code. When an entry point reaches a deployer chain (`deploy`,
`deploy_v2`, `upload_contract_wasm`, or `update_current_contract_wasm`) without
authorizing the caller, any account may be able to install attacker-controlled
code, replace an existing contract, or consume the contract's deployment quota.

## How it is detected

For each public function in a `#[contractimpl]` block, the detector checks the
function body and its intra-file helpers for:

1. a method call named `deployer` (the `env.deployer()` accessor), and
2. at least one deploy-like call (`deploy`, `deploy_v2`,
   `upload_contract_wasm`, or `update_current_contract_wasm`).

If a `require_auth` or `require_auth_for_args` fact is present anywhere in the
same scope, no finding is reported. Otherwise the `deployer` call is reported
with concrete source evidence.

## Limitations

This is a syntactic heuristic. It cannot verify that the authorizing address is
the correct administrator, that the authorization is bound to the deployment,
or that authorization is not enforced by a cross-contract callee. It also does
not trace a deployer value stored in a struct field or returned from another
file.

## False positives

- Deployment is intentionally permissionless and protected by another mechanism
  outside the analyzed scope.
- Authorization is enforced by a callee or an external contract.
- An administrator address is authorized in a helper that the intra-file walk
  cannot resolve (for example in another file).

## Remediation

Load a trusted administrator address from storage and authorize it before
deploying:

```rust
let admin: Address = env
    .storage()
    .instance()
    .get(&DataKey::Admin)
    .ok_or(Error::NotInitialized)?;
admin.require_auth();

env.deployer()
    .with_current_contract(salt)
    .deploy(wasm_hash);
```

Bind the authorization to the operation when possible and reject callers that
are not allowed to deploy.
