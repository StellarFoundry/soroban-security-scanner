# SS-018 — Unchecked integer cast

- **Severity:** medium
- **Confidence:** low
- **Category:** arithmetic

## Problem

Rust's `as` operator between integer types truncates the high bits instead of
failing. A contract that narrows a caller-supplied amount, timestamp, or counter
with `as` can therefore silently turn an out-of-range value into a small
unintended one. That is a classic source of balance and accounting bugs: a large
`i128` amount cast to `u32`, or a stored `u64` balance narrowed to `u32`, wraps
without any error.

## How it is detected

The detector visits public functions in `#[contractimpl]` blocks and inspects
every `expr as Type` cast. It reports a finding when all of the following hold:

- the source and target types are recognizable Rust integer types;
- the target is **narrower** than the source (a narrowing cast);
- the operand comes directly from a function parameter or from a value read from
  contract storage.

Same-width and widening casts are ignored, as are casts of literals, computed
expressions, and local variables that were not read from storage.

## Limitations

- This is a syntactic heuristic with no type inference. The source type is only
  known when the source makes it visible: a parameter type, a local type
  annotation, an integer literal suffix, or a storage `get::<_, T>` turbofish.
  A cast whose source type cannot be seen is not reported.
- Only direct operands are classified. A cast of a helper return value or of an
  expression derived from a parameter is not traced back to its origin.
- Signedness is not considered. `i64 as u64` is same-width and is ignored, even
  though it reinterprets negative values.
- It cannot prove that the value is out of range at run time; the operand may be
  checked elsewhere. Review each finding in context.

## False positives

- Widening conversions such as `u32 as u64`.
- Same-width casts such as `u32 as u32`.
- Safe fallible conversions using `u32::try_from(value)` or `value.try_into()`.
- Casts of literals, constants, or local values computed without storage or
  parameter input.

## Remediation

Use a fallible conversion and handle the error:

```rust
let amount: u32 = u32::try_from(amount)
    .map_err(|_| Error::AmountOutOfRange)?;
```

`TryFrom`/`try_into` reject out-of-range values instead of truncating, so an
invalid input becomes a typed contract error rather than a corrupted value.
