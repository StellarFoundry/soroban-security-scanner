# SS-018 — Unchecked integer cast in a contract entry point

- **Severity:** medium
- **Confidence:** low
- **Category:** arithmetic

## Problem

A public contract entry point uses an `as` cast to narrow or change the
signedness of an integer value derived from a function parameter or contract
storage. In Rust, primitive `as` casts between integer types never panic:
narrowing casts silently truncate high-order bits and signed/unsigned casts
reinterpret two's-complement bit patterns. Truncated or wrapped amounts,
balances, and counters can corrupt accounting and enable exploits.

## How it is detected

For every public function inside a `#[contractimpl]` block, the detector inspects
explicit `expr as Ty` cast expressions where `Ty` is a primitive integer type and
the operand references an integer parameter or a value read from contract
storage (`env.storage()...get(...)`). Widening and same-width casts that preserve
all values of the source type (for example `u32 as u64` or `u64 as i128`) are
ignored; narrowing and sign-changing casts are reported.

## Limitations

- Syntactic and local type-annotation analysis only; the detector does not run
  full Rust type inference across complex method chains or helper functions.
- Cannot prove whether a preceding range check (`if amount >= 0 && amount <= u64::MAX as i128`)
  already guarantees that the cast is lossless.
- Reports **low confidence** because explicit range guards may make a cast safe
  in context.

## False positives

- Narrowing casts preceded by an explicit bounds check on the operand.
- Bit-manipulation or encoding routines that intentionally truncate to low bits.

## Remediation

Replace narrowing or sign-changing `as` casts with fallible conversions using
`core::convert::TryFrom` / `TryInto` (`u64::try_from(value)` or
`value.try_into()`) and handle the `Err` case with a typed contract error.
