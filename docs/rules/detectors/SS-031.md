# SS-031 — Event topic derived from a caller-controlled parameter

- **Severity:** medium
- **Confidence:** low
- **Category:** events

## Problem

Soroban events have a topic list that off-chain indexers use to group, route, and
sometimes trust events. When a contract copies a caller-supplied parameter into a
topic, the caller chooses which topic the event appears under. A malicious caller
can therefore publish a spoofed event that looks like a trusted event type (for
example a fake `transfer`, `admin`, or `mint` event), misleading indexers,
dashboards, and monitoring that key on the topic.

The safe pattern is a constant topic that names the event type, with all
caller-controlled values in the event data payload.

## How it is detected

The detector visits public functions in `#[contractimpl]` blocks. For each method
call named `publish` whose receiver contains `events`, it inspects the first
argument (the topic list) and reports when any identifier in that expression is a
function parameter.

Constant expressions do not trigger:

- string and integer literals;
- `symbol_short!(...)` and `symbol!(...)` macros;
- `Symbol::new(&env, "...")` with a literal value;
- paths to constants such as `TOPIC` or `DataKey::Transfer`;
- any expression that only uses the `Env` parameter.

Parameters in the second argument (the data payload) are expected and are not
reported.

## Limitations

- This is a syntactic heuristic. It follows direct references to parameters but
  does not perform taint analysis: a local variable or helper return value that
  was derived from a parameter is not traced back to it.
- Macro token streams are opaque to the AST visitor, so a topic built inside a
  macro is not inspected.
- Parameters passed through a struct field or collection re-exported from a
  caller-controlled value may not be recognized.
- It cannot know whether an indexer actually trusts the topic, so it reports low
  confidence. Using a parameter as a topic can be legitimate (for example a
  per-account topic); review each finding in context.

## False positives

- Constant topics with caller data in the payload.
- A parameter deliberately used as a per-record topic and validated against a
  known set of values.
- Non-event `publish` methods (for example a message queue) and private helpers.

## Remediation

Use a constant event-type topic and move caller-controlled values into the data:

```rust
env.events().publish(
    (symbol_short!("transfer"), Symbol::new(&env, "v1")),
    (from, to, amount),
);
```

If a parameter must be part of the topic, validate it against an allowlist of
expected topic values before publishing, and document why the topic is trusted.
