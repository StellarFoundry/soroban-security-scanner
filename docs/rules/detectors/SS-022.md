# SS-022 — Duplicate or invalid symbol_short! storage key

- **Severity:** high
- **Confidence:** high
- **Category:** storage

## Problem

Two distinct `Symbol` constants in the same contract file resolve to the same
`symbol_short!` literal, or a `symbol_short!` invocation uses a literal longer
than 9 characters or outside `[a-zA-Z0-9_]`. Duplicate key constants cause
unrelated contract state to overwrite the same storage slot.

## How it is detected

The detector inspects `const` and `static` items initialized with
`symbol_short!("...")` in each file and reports duplicate literals assigned to
different constant names, as well as any `symbol_short!` literal that exceeds 9
characters or contains invalid characters.

## Limitations

- Single-file scope; collisions across separate modules/files are not checked.

## False positives

- Intentional aliases where a deprecated constant name is kept for backward
  compatibility.

## Remediation

Assign a unique `symbol_short!` literal (at most 9 ASCII alphanumeric/underscore
characters) to each storage key constant, or use a typed
`#[contracttype] enum DataKey`.
