# SS-022 - Unsafe symbol_short key

- **Severity:** medium
- **Confidence:** medium
- **Category:** storage

## Problem

A contract uses `symbol_short!` for a storage key with a literal longer than the
documented short-symbol limit, or builds the symbol from caller-controlled input.
An overlong literal does not describe the symbol the author expects (and does not
compile with current SDKs), while a caller-built short symbol can deliberately
collide with another key and overwrite or misread storage.

## Documented limit

`soroban-sdk` 20.x through 23.x encodes short symbols as at most **nine ASCII
characters**. `symbol_short!` only accepts a string literal within that limit and
rejects longer input. The detector uses nine characters as the limit.

## How it is detected

The detector visits public functions in `#[contractimpl]` blocks:

- A `symbol_short!` invocation whose token stream parses as a string literal is
  measured; a value longer than nine characters is reported.
- A non-literal invocation is reported when its tokens reference a function
  parameter that is not `Env`, or a simple local alias derived from such a
  parameter.

Calls in private helpers and invocations whose tokens reference a constant are
not reported.

## Limitations

- This is a syntactic check. It does not evaluate constants or macro expansion.
- Only simple `let` aliases of caller input are followed.
- Collisions between two distinct constant keys are not detected; the rule
  targets caller-controlled keys per the design.
- The nine-character limit is versioned to the currently supported SDKs and must
  be revisited if Soroban changes the short-symbol representation.

## False positives

- A literal of exactly nine characters, which is valid.
- A constant identifier such as `symbol_short!(KEY)` where `KEY` is a compile-time
  constant.
- A dynamic key that uses `Symbol::new(&env, value)` instead of the short macro.

## Remediation

Use a constant short literal, or use the full symbol constructor for longer or
dynamic values:

```rust
let key = symbol_short!("transfer");
// For longer or dynamic values:
let key = Symbol::new(&env, value);
```

Never derive a storage key directly from caller input. Map user input through an
allowlist of known keys.
