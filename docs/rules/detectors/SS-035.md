# SS-035 — Ignored checked-arithmetic result

- **Severity:** high
- **Confidence:** medium
- **Category:** arithmetic

## Problem

`checked_add`, `checked_sub`, `checked_mul`, and related APIs return `None` on
overflow instead of panicking. Discarding that result silently ignores the
overflow, reintroducing the exact bug the checked API exists to prevent.

## How it is detected

For every public `#[contractimpl]` entry point, the detector finds checked-math
calls. It reports a call whose result is not handled: a bare statement, a
discard into `_`, or any use other than direct handling by `?`, `match`, `if let`,
`return`, or an `unwrap`/`unwrap_or`/`is_some`-style handler.

## Limitations

- Only direct handling is recognized. A result stored in a local and inspected
  later is reported.
- Helpers are not traced.

## False positives

- A checked result stored and inspected in a helper, or handled through a
  wrapper the detector does not recognize.

## Remediation

Handle the result explicitly.

```rust
let value = amount.checked_add(1).ok_or(Error::Overflow)?;
// or
let value = amount.checked_add(1).unwrap_or(0);
```
