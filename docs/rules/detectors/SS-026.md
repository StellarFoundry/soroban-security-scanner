# SS-026 — TTL constant outside the expected range

- **Severity:** low
- **Confidence:** low
- **Category:** resource-usage

## Problem

Soroban storage entries expire unless their time-to-live (TTL) is extended.
`extend_ttl` and `set_ttl` take TTL values measured in ledgers. A literal that
is zero or too small expires an entry almost immediately and can lose data; a
literal above the network maximum is rejected or signals a unit mistake, such as
passing seconds where ledgers are expected. Ad-hoc literals also make it hard to
audit the contract's retention policy.

## How it is detected

The detector scans every parsed source in the project. For each method call
named `extend_ttl` it reads the literal `threshold` (argument 1) and `bump`
(argument 2); for each `set_ttl` it reads the literal `ttl` (argument 1). Only
plain integer literals are considered, with `_` separators and integer type
suffixes tolerated. A value outside the documented expected range is reported
together with the concrete value, for example `threshold=0`.

### Documented expected range

- Minimum: **1 ledger** (a zero TTL expires immediately).
- Maximum: **3,110,400 ledgers**, the network cap of about six months
  (180 days at roughly 5 seconds per ledger).

The rule uses severity `low` and confidence `low`: an unusual but intentional
value, or a different local convention, may be legitimate.

## Limitations

The detector cannot evaluate computed TTL expressions (`threshold + 1`,
constants imported from another file, or values read from storage). It only sees
literal arguments and reports syntactic evidence.

## False positives

- A project that deliberately uses a value outside the network range and handles
  the resulting host error.
- Named constants that resolve to valid values (not inspected).
- Test-only constants that never run on chain.

## Remediation

Define named TTL constants from a single documented policy and use them for
every key:

```rust
const DAY_IN_LEDGERS: u32 = 17_280;
const BUMP_AMOUNT: u32 = 30 * DAY_IN_LEDGERS;
const LIFETIME_THRESHOLD: u32 = DAY_IN_LEDGERS;

env.storage()
    .persistent()
    .extend_ttl(&key, LIFETIME_THRESHOLD, BUMP_AMOUNT);
```
