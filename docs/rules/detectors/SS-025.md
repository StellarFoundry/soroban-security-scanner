# SS-025 — Unbounded String or Bytes parameter persisted to storage

- **Severity:** medium
- **Confidence:** low
- **Category:** resource-usage

## Problem

A public contract entry point accepts a dynamically sized `String` or `Bytes`
parameter and writes it to persistent or instance storage without checking
`.len()`. Storing unbounded variable-length payloads inflates ledger rent fees
and can push entry size past Soroban host limits.

## How it is detected

Within a public `#[contractimpl]` entry point, the detector identifies
parameters typed as `String` or `Bytes` (excluding fixed-size `BytesN<N>`) and
reports `storage().*.set(...)` calls that persist those parameters without a
preceding `.len()` or `.is_empty()` check.

## Limitations

- Length validation inside a helper function is not tracked.

## False positives

- Admin-only metadata setters where payload size is controlled off-chain.

## Remediation

Enforce an explicit maximum byte/character length on `String` and `Bytes`
parameters before writing them to contract storage.
