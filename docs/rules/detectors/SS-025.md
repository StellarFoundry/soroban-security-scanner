# SS-025 — Unbounded string/bytes persisted from caller input

- **Severity:** medium
- **Confidence:** medium
- **Category:** storage

## Problem

Persisting a caller-controlled `String` or `Bytes` value without a length bound
lets an attacker grow ledger entries without limit. Larger entries raise rent,
and unbounded growth can eventually exceed ledger limits — a denial of service.

## How it is detected

For every public `#[contractimpl]` entry point, the detector identifies
parameters whose rendered type is Soroban `String` or `Bytes`. It then inspects
storage `set`/`update` writes (including the UFCS form) and reports when the
written value references such a parameter, unless a visible `.len()` comparison
on that parameter appears before the write.

## Limitations

- A bound enforced in a helper is not seen (helpers are not traced).
- Only visible `.len()` comparisons are recognized; a manual check on `bytes()`
  length or a wrapper type is not.
- Type detection reads the written type text and does no inference.

## False positives

- Values bounded by a check the detector cannot see (for example in a helper or
  a called validator).

## Remediation

Reject or truncate values above an explicit maximum before persisting them, or
store a fixed-size hash of the value instead.

```rust
const MAX_NAME: u32 = 64;
if name.len() > MAX_NAME {
    return Err(Error::TooLong);
}
env.storage().persistent().set(&DataKey::Name, &name);
```
