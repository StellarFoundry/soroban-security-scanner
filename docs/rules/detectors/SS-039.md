# SS-039 - Persistent storage read without TTL management

- **Severity:** medium
- **Confidence:** low
- **Category:** storage

## Problem

A contract entry point reads a value from persistent storage but never extends
the entry's time-to-live. Persistent entries expire. If the code assumes the
value is still present, an expired entry can change the contract's behaviour,
make a required configuration value disappear, or block an operation that
depends on it.

## How it is detected

For every public `#[contractimpl]` entry point, the detector collects
`persistent().get(...)` and `persistent().get_unchecked(...)` calls from the
function body and the intra-file helpers it calls. It reports a read only when
no TTL manager (`extend_ttl`, `set_ttl`, or `bump`) is present in that same fact
set. The evidence names the entry function and the read expression.

Only the persistent storage class is inspected. Instance and temporary reads are
not reported: instance TTL is managed with the contract instance, and temporary
entries are expected to expire.

## Ambiguity is not reported

A TTL call is not tied to a specific key by this analysis. If any TTL management
is visible in the function or its helpers, the detector assumes it may cover the
read and reports nothing. This avoids guessing when the code extends an unrelated
key or delegates TTL maintenance elsewhere. Reads in private helpers that no
entry point calls are ignored.

## Limitations

- Syntactic and per entry point. Cross-file helpers and trait dispatch are not
  followed.
- `has`, `get_ttl`, and iteration APIs are not treated as reads by this rule.
- A TTL call anywhere in the same entry point or intra-file helpers suppresses
  every read finding for that entry point.
- The rule does not check that the TTL is long enough or that the extension uses
  the same key as the read.
- TTL maintained by a separate maintenance entry point or outside the analyzed
  file is not visible.

## False positives

- A reader that legitimately tolerates an expired entry, for example an optional
  cache in persistent storage.
- A contract whose TTL is refreshed centrally by an operator entry point.
- A read of an entry that was just written by the same call and has a fresh TTL.

## Remediation

Refresh the TTL for the entry the read depends on:

```rust
pub fn load(env: Env) -> u32 {
    let value = env.storage().persistent().get(&KEY).unwrap();
    env.storage().persistent().extend_ttl(&KEY, 100, 1_000);
    value
}
```

If TTL is managed by a separate maintenance entry point, suppress this rule for
the reader with a documented justification.
