# SS-019 — Ignored cross-contract call result

- **Severity:** medium
- **Confidence:** medium
- **Category:** cross-contract

## Problem

A cross-contract client call such as `client.transfer(...)` or
`client.balance(...)` returns a `Result`. When the call is used as a bare
statement (`client.transfer(...);`) or discarded into `_`, the caller never
learns that the call failed. A failed transfer, approval, or state change then
looks successful, which can leave balances, accounting, or emitted events
inconsistent and can silently skip follow-up logic.

## How it is detected

For every function in a `#[contractimpl]` block, the detector:

1. Tracks local variables initialized from a client constructor such as
   `TokenClient::new(...)` or `token::Client::new(...)`.
2. Finds method calls whose receiver is one of those client variables.
3. Reports the call when its result is discarded: it is the expression of a
   statement with a trailing semicolon, or the initializer of `let _ = ...`.

Calls whose result is assigned to a named binding, returned as a tail
expression, propagated with `?`, used in a `match`, or tested with `if let` are
not reported.

## Limitations

This is a syntactic check. The detector does not know the called method's return
type, so a client method that returns `()` is still reported. It also cannot
follow client variables across helper functions or across files, and it does not
resolve type aliases that hide the `Client` name.

## False positives

- A cross-contract method that genuinely returns `()`.
- A call whose result is intentionally ignored for a documented reason, such as
  a best-effort notification where failure is acceptable.
- Clients stored in struct fields or passed as function parameters rather than
  created in a local `let` binding.

## Remediation

Handle the result explicitly:

```rust
client.transfer(&from, &to, &amount)?;
```

or match on it when a typed error is needed:

```rust
match client.try_transfer(&from, &to, &amount) {
    Ok(Ok(_)) => {}
    Ok(Err(error)) => return Err(Error::TransferFailed),
    Err(_) => return Err(Error::CallFailed),
}
```

If ignoring a result is intentional, add a comment and suppress this rule for
the specific line.
