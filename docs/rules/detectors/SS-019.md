# SS-019 — Ignored cross-contract call result

- **Severity:** medium
- **Confidence:** medium
- **Category:** cross-contract

## Problem

A contract entry point invokes a cross-contract client method and explicitly
discards its return value (`let _ = client.call(...)` or an unhandled
`client.try_*(...);` statement). Ignoring a `try_*` result or discarding a
cross-contract return value can allow execution to continue after the remote
contract failed or returned a status that must be checked.

## How it is detected

Within a public `#[contractimpl]` entry point, the detector tracks local
variables bound to `*Client::new(...)` and flags `let _ = client.<method>(...)`
bindings as well as bare `client.try_*(...);` expression statements.

## Limitations

- Intra-function only; client calls wrapped inside helper functions are not
  followed.
- Direct panicking client calls (`client.transfer(...);`) that return `()` are
  not flagged because the Soroban SDK client aborts the transaction on failure.

## False positives

- Best-effort notification hooks where the contract intentionally ignores a
  remote failure.

## Remediation

Handle the result of every cross-contract call explicitly. When using `try_*`
client methods, propagate or match on the outer and inner `Result` values
instead of discarding them with `let _ =` or a bare statement.
