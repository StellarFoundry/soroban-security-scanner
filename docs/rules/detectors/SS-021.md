# SS-021 — Durable state stored in temporary storage

- **Severity:** high
- **Confidence:** medium
- **Category:** storage

## Problem

A contract entry point writes a key that represents durable state (such as
admin, owner, balance, allowance, or reserve) into `storage().temporary()`.
Temporary storage entries are permanently deleted when their TTL expires and
cannot be restored from the ledger archive, which can brick access control or
erase user balances.

## How it is detected

Within a public `#[contractimpl]` entry point, the detector inspects
`storage().temporary().set(...)` and `.update(...)` calls and flags those whose
key expression matches durable state identifiers (`admin`, `owner`, `balance`,
`total_supply`, `allowance`, `reserve`, `treasury`, `governor`, `stake`).

## Limitations

- Relies on key naming conventions; opaque numeric keys are not flagged.
- Temporary caches whose key names happen to include words like `balance` may be
  flagged.

## False positives

- Short-lived quote or snapshot caches that intentionally expire and include a
  durable-sounding word in the key name.

## Remediation

Store administrative configuration in `storage().instance()` or
`storage().persistent()`, and store per-user balances, allowances, and
positions in `storage().persistent()` so they can be restored if archived.
