# SS-043 - Hardcoded Stellar network passphrase

- **Severity:** medium
- **Confidence:** high
- **Category:** configuration

## Problem

Stellar transaction signatures include the network passphrase. Using a fixed
passphrase in shared source can make a deployment sign for the wrong network
when code is reused across test, staging, and production environments.

## How it is detected

The rule reports exact string literals equal to the canonical Public, Testnet,
Futurenet, or Standalone Stellar network passphrases. It also reports
fully-qualified `stellar_sdk` paths selecting `PUBLIC`, `TESTNET`, `FUTURENET`,
or `STANDALONE` from a `Network` or `Networks` module/type. Findings point to
the literal or constant path and name the matched value.

No value is inferred from a variable name, a partial string, an environment
lookup, or an arbitrary path. The rule does not resolve imports or aliases.

## Limitations

- Only the four documented canonical passphrases and the exact qualified
  constant spellings described above are recognized. New networks or SDK path
  spellings are not reported until explicitly added.
- Values assembled at runtime, loaded from files, or hidden behind aliases are
  not followed.
- A fixed network may be intentional for a single-network deployment. The rule
  cannot determine deployment topology or operational configuration.

## False positives

- A command-line tool intentionally restricted to one network.
- A test that embeds a canonical passphrase as test data.
- A checked-in example that is intentionally specific to one network.

Keep the fixed choice only when the deployment is intentionally single-network;
otherwise configure the passphrase per environment.

## Remediation

Read the passphrase from deployment configuration or an environment variable,
and verify that it matches the intended network before signing. Keep local
development and production settings separate.
