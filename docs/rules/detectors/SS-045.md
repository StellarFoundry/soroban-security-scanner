# SS-045 — Cross-contract call without error handling

- **Severity:** medium
- **Confidence:** medium
- **Category:** cross-contract

## Problem

A cross-contract client call returns a fallible result. When the entry point
discards that result — as a bare statement, through `let _ =`, or by binding it
to a name that is never used — a failed call looks successful. Partial state,
unbalanced accounting, or skipped follow-up logic can then go unnoticed.

## How it is detected

For each public function in a `#[contractimpl]` block, the detector:

1. Finds local variables initialized from a client constructor such as
   `token::Client::new(...)` or `TokenClient::new(...)`.
2. Reports a client method call whose result is discarded:
   - the call is the expression of a statement with a trailing semicolon, or
   - the call initializes `let _ = ...`, or
   - the call initializes a named binding that is never referenced again in the
     same function.

The result is considered handled — and is not reported — when it is propagated
with `?`, inspected with `match` or `if let`, returned, or passed through
`unwrap`, `unwrap_or*`, `expect`, `map_err`, `ok`, `err`, `is_ok`, or `is_err`.

## Limitations

This is a syntactic check. The detector does not know the called method's return
type, so a client method that genuinely returns `()` is still reported. It does
not follow client variables across helper functions or files, does not resolve
type aliases that hide the `Client` name, and only inspects public
`#[contractimpl]` functions.

## False positives

- A cross-contract method that genuinely returns `()`, where no error can be
  observed.
- A named binding that is used only for debugging or logging in a way the
  detector cannot classify; such a binding counts as used and is not reported.
- Destructuring, free-function arguments, and other ambiguous uses are not
  reported: ambiguity is recorded as no finding, never guessed.

## Remediation

Propagate the error:

```rust
client.transfer(&from, &to, &amount)?;
```

or handle it deliberately:

```rust
match client.try_transfer(&from, &to, &amount) {
    Ok(Ok(_)) => {}
    Ok(Err(error)) => return Err(Error::TransferFailed),
    Err(_) => return Err(Error::CallFailed),
}
```

If ignoring a result is intentional, bind it to an `_`-prefixed name and record
why.
