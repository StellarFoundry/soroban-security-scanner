# SS-030 — Token client built from an unvalidated caller address

- **Severity:** high
- **Confidence:** low
- **Category:** token

## Problem

Constructing a `token::Client` from a caller-supplied address without checking it
against the contract's configured token lets an attacker substitute a malicious
token contract. The substitution can change balances, transfer semantics, or
transfer destinations.

## How it is detected

For every public `#[contractimpl]` entry point, the detector finds token client
constructors (`token::Client::new`, including aliased imports). When the address
argument references a function parameter, it reports the construction unless a
storage read and a comparison involving that parameter occur before it.

## Limitations

- Syntactic only; helpers and indirect validation are not traced.
- A comparison unrelated to the stored configuration can suppress the finding.
- Only constructors named `new` on a token client are recognized.

## False positives

- Addresses supplied by trusted wrappers that validate before calling in.
- Comparisons against configuration that the detector cannot resolve.

## Remediation

Compare the supplied token address with the address stored at configuration time
and reject mismatches before constructing the client.

```rust
let configured: Address = env.storage().persistent().get(&Key::Token).unwrap();
if token_id != configured {
    panic!("unexpected token");
}
let client = token::Client::new(&env, &token_id);
```
