# SS-024 - Missing contracttype on boundary types

- **Severity:** medium
- **Confidence:** medium
- **Category:** configuration

## Problem

A contract entry point accepts or returns a local struct or enum that is not
annotated with `#[contracttype]`. Soroban needs boundary types to be
XDR-serializable, and a missing attribute commonly fails at runtime (or when a
client invokes the contract) instead of at compile time, making it easy to miss
in review.

## How it is detected

The detector visits public functions in `#[contractimpl]` blocks. It builds the
set of local types declared in the same file and subtracts the ones carrying
`#[contracttype]`. A parameter or return type that names a remaining local type,
including inside containers such as `Vec<Payload>` or `Option<Payload>`, is
reported.

SDK types, primitives, and private helper signatures are ignored.

## Limitations

- Only the same parsed file is considered; a type imported from another module
  is not resolved.
- Types are matched by name token, not by semantic resolution.
- A type may be made serializable by a custom implementation that this heuristic
  cannot see.

## False positives

- A local type serialized through a documented wrapper or manual XDR conversion.
- A local type only used in a private helper (not reported).

## Remediation

Annotate the type:

```rust
#[contracttype]
pub struct Payload {
    pub amount: i128,
}
```

Or replace it with an SDK type (`Address`, `Bytes`, `Symbol`, a primitive) when
that is the intended boundary contract.
