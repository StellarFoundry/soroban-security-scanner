# SS-024 — Missing #[contracttype] on boundary struct or enum

- **Severity:** medium
- **Confidence:** high
- **Category:** configuration

## Problem

A user-defined `struct` or `enum` appears in the parameter or return type of a
public `#[contractimpl]` entry point without being annotated with
`#[contracttype]` or `#[contracterror]`. Types that cross the Soroban host
boundary without `#[contracttype]` lack generated `Val` conversion
implementations and fail host serialization.

## How it is detected

For each file, the detector inventories local `struct` and `enum` items that
carry neither `#[contract]`, `#[contracttype]`, nor `#[contracterror]`, and
reports those referenced in the parameter or return types of a public
`#[contractimpl]` entry point.

## Limitations

- Single-file scope; types imported from other modules are not resolved.

## False positives

- Types that manually implement `TryFromVal`/`IntoVal` without using the macro.

## Remediation

Annotate every custom struct or enum that crosses the contract boundary or is
persisted in contract storage with `#[contracttype]` (or `#[contracterror]` for
error enums).
