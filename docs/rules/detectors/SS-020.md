# SS-020 - Unvalidated XDR or bytes deserialization

- **Severity:** medium
- **Confidence:** low
- **Category:** error-handling

## Problem

A contract entry point decodes caller-supplied bytes or XDR with `from_xdr`,
`from_bytes`, or `try_from` without checking the payload length or handling a
fallible decode result. Malformed or attacker-chosen input can produce an
unexpected value, panic the contract, or bypass validation that the author
assumed happened during decoding.

## How it is detected

The detector visits public functions in `#[contractimpl]` blocks. It treats a
parameter as caller-controlled bytes when its type contains `Bytes`, `u8`,
`XDR`, or `blob`, and follows simple local aliases of those parameters. It
reports:

- a `from_xdr` or `from_bytes` call whose receiver or arguments reference a
  tainted value, and
- a `try_from` call whose arguments reference a tainted value,

unless the same tainted value has a `.len()` comparison before the call, or the
call result is handled by `?`, `match`, `unwrap`, `expect`, `unwrap_or`,
`map`, `map_err`, or a similar adapter.

Storage-derived `Bytes` locals are not tainted, because they do not come from the
caller.

## Limitations

- This is a syntactic, heuristic check. It does not type-check the decoded type
  or prove that a length check is correct for the format.
- Local aliases are followed only through simple `let` bindings; values passed
  through helper functions or re-bound in complex expressions are not tracked.
- A length check anywhere before the call suppresses the finding even if the
  checked value differs from the decoded value.
- Macro-generated deserialization is not inspected.

## False positives

- A payload whose length was validated by another function or a type invariant.
- A fallible decode whose error is converted through a custom adapter not in the
  handler list; add an inline suppression with a reason.
- Decoding trusted constants or values read from storage.

## Remediation

Check the length and handle the result explicitly:

```rust
let expected = 4usize;
if payload.len() != expected {
    return Err(Error::InvalidLength);
}

let value = u32::from_xdr(&env, &payload);
let amount = i128::try_from(value).map_err(|_| Error::InvalidValue)?;
```
