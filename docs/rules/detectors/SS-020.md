# SS-020 — Unvalidated XDR or Bytes deserialization

- **Severity:** medium
- **Confidence:** low
- **Category:** resource-usage

## Problem

A public contract entry point deserializes an untrusted parameter via `from_xdr`
without first bounding its byte length or validating the payload. Unbounded XDR
deserialization on attacker-controlled `Bytes` can exhaust Soroban CPU/memory
budgets or fail unexpectedly on malformed input.

## How it is detected

Within a public `#[contractimpl]` entry point, the detector finds `from_xdr`
calls whose arguments reference a function parameter and reports those that have
no preceding `.len()`, `.is_empty()`, `.slice()`, or comparison check on that
parameter.

## Limitations

- Length validation performed inside a helper function is not tracked.
- Fixed-size types still incur XDR parsing overhead proportional to input handling.

## False positives

- Entry points where the caller is a trusted admin or where length is bounded
  by a helper before `from_xdr`.

## Remediation

Validate the input `Bytes` length against an explicit upper bound before calling
`from_xdr`, and handle deserialization errors gracefully.
