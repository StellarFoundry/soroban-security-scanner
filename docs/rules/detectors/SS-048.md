# SS-048 - Unbounded event payload

- **Severity:** medium
- **Confidence:** medium
- **Category:** events

## Problem

A contract publishes an event whose payload type has no fixed size:

```rust
#[contractimpl]
impl Contract {
    pub fn record(env: Env, items: Vec<Address>) {
        env.events().publish((symbol_short!("record"),), items);
    }
}
```

Event payloads are written to the ledger, and the caller chooses how many
elements a `Vec` or `Map` holds, how many bytes a `Bytes` value carries, and how
long a `String` is. A large payload raises the transaction fee and, past the
network limits, makes the emission fail. An attacker can therefore make a
legitimate operation unaffordable or abort, and the same pattern can let a
deployer write more ledger data than the contract design intended.

## How it is detected

The detector examines public `#[contractimpl]` entry points and the payload
argument of `events().publish(topics, payload)`. It reports when the payload
mentions a parameter whose declared type is one of:

- `Vec<...>`
- `Map<...>`
- `Bytes`
- `String`

The type must be visible in the parameter list. A visible `.len()` comparison
that mentions the parameter and appears before the publish suppresses the
finding, because the payload is then bounded in the entry point.

The detector also inspects `#[contractevent]` struct declarations and reports a
field whose declared type is one of the unbounded types above. `BytesN<N>` is
fixed-size and is not reported.

## Limitations

- It does not infer types through locals, helper return values, storage reads, or
  cross-contract calls. Only parameter types and `#[contractevent]` field types
  are visible.
- It does not measure constants, so a length bound enforced in another function
  or by a custom type is not recognized.
- It does not distinguish a payload that is large but harmless from one that is
  security-relevant.
- The `.len()` check is matched syntactically against the publish location, not
  proven on every control-flow path.
- It only inspects the second `publish` argument. A payload built after the call
  (or passed through a helper) is not traced.

## False positives

- A payload that is fixed-size, such as `BytesN<32>`, `u32`, `i128`, or
  `Address`.
- A `Vec`, `Map`, `Bytes`, or `String` argument whose length is checked against
  a maximum before publishing.
- Publishing only a length, a count, or a hash derived from the collection.
- An unbounded value received by an entry point but never placed in an event.
- `#[contractevent]` structs whose fields are all fixed-size.
- Publishing from a private helper that the detector does not treat as an entry
  point.

## Remediation

Bound the payload and prefer a summary event:

```rust
const MAX_ITEMS: u32 = 32;

if items.len() > MAX_ITEMS {
    return Err(Error::TooManyItems);
}

// Publish a fixed-size summary rather than the whole collection.
env.events()
    .publish((symbol_short!("record"),), (items.len(), digest));
```

Store the full collection off the event path, or commit to a hash, and document
the maximum size the event is expected to carry.
