# SS-027 — current_contract_address() used as require_auth subject

- **Severity:** high
- **Confidence:** high
- **Category:** authorization

## Problem

A contract entry point calls `require_auth` or `require_auth_for_args` on
`env.current_contract_address()` (either directly or through a local binding).
In the Soroban host, the currently executing contract is implicitly authorized
for its own frame, so this check succeeds unconditionally and provides zero
caller access control.

## How it is detected

Within a public `#[contractimpl]` entry point, the detector tracks direct
`env.current_contract_address().require_auth*()` calls as well as local
variables initialized from `env.current_contract_address()` on which
`require_auth` or `require_auth_for_args` is called.

## Limitations

- Intra-function only; `current_contract_address()` passed into a helper
  function is not tracked.

## False positives

- None in normal contract code; authorizing the current contract within its own
  frame is always a no-op.

## Remediation

Call `require_auth()` on the external caller or stored administrator `Address`
that must approve the invocation, never on `env.current_contract_address()`.
