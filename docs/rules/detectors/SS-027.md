# SS-027 — Contract's own address used as an authorization subject

- **Severity:** high
- **Confidence:** medium
- **Category:** authorization

## Problem

`env.current_contract_address().require_auth()` authorizes the contract itself,
not the caller. Because any invocation satisfies this check, it defeats the
intended access control and can let unauthorized callers perform privileged
actions.

## How it is detected

For every public `#[contractimpl]` entry point, the detector reports
`require_auth` or `require_auth_for_args` calls whose receiver renders as
`current_contract_address(...)`.

## Limitations

- Only the receiver expression chain is matched; an address stored in a local
  variable first is not resolved.
- Helpers are not traced.

## False positives

- Deliberate self-authorization in a contract that is genuinely acting as its
  own authority (rare; document it and suppress the finding).

## Remediation

Authorize the actual caller. Take an `Address` parameter, or read the stored
owner/admin address, and call `require_auth` on that value.

```rust
pub fn guarded(env: Env, caller: Address) {
    caller.require_auth();
    // ...
}
```
