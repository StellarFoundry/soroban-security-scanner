# SS-036 - Deprecated SDK API usage

- **Severity:** low
- **Confidence:** medium
- **Category:** dependencies

## Problem

The contract calls a Soroban SDK API that has been deprecated or removed. The
code may fail to build against a newer SDK, and the old API can carry stale
behavior or security assumptions.

## How it is detected

The detector walks method and function calls and compares them with a versioned
table of known deprecated APIs. A call matches when its name and receiver
fragment match a table row.

## Deprecated API table

| API | Deprecated since | Replacement |
| --- | ---------------- | ----------- |
| `Env::logger().log(...)` | 20.0.0 | `env.events().publish(...)` |
| `Env::budget()` | 20.0.0 | `env.cost_estimate()` |
| `Address::random(...)` | 21.0.0 | derive from ledger state or validated caller input |

Add a row with the version and replacement whenever an SDK API is retired and
document it here.

## Limitations

- Static, name-based matching only; aliases and re-exports can hide a call.
- The table is intentionally small and must be maintained per SDK version.
- A same-named method on a non-SDK type is not reported when the receiver
  fragment does not match.

## False positives

- A user-defined type with the same method name and a matching receiver name.
- Code that intentionally targets an older pinned SDK.

## Remediation

Use the replacement for the SDK version in use, then re-run the scanner after
upgrading `soroban-sdk`.
