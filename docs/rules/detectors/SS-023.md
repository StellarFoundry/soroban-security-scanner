# SS-023 — Sensitive-looking data published in events

- **Severity:** medium
- **Confidence:** low
- **Category:** events

## Problem

Ledger data is public forever. Publishing a secret, seed, preimage, or signing
key in an event is an irreversible disclosure that cannot be undone.

## How it is detected

For every public `#[contractimpl]` entry point, the detector inspects
`env.events().publish(...)` calls. It reports when a published argument
references a parameter whose name suggests secret material (`secret`, `seed`,
`proof`, `preimage`, `mnemonic`, `passphrase`, `password`, `key`, `private_key`,
`signing_key`), or contains a string literal with such a name.

## Limitations

- Purely name-based; it does not track data flow or know a value's contents.
- A secret passed through an innocently named local variable is missed.
- Helpers are not traced.

## False positives

- Public keys or generic `key` parameters that are safe to publish.
- Identifier names that merely contain a hint word.

The rule reports low confidence for this reason; treat a finding as a prompt to
review, not as proof of disclosure.

## Remediation

Do not publish secrets or secret-derived values. Commit to a hash if you must
prove knowledge of a value, and keep key material, seeds, and preimages
off-chain.

```rust
env.events().publish(symbol_short!("commit"), sha256(&secret));
```
